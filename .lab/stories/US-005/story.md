# User Story

## Statement

As a person using an AI coding harness,
I want Catfish Lab to explain its value and move ordinary work forward with minimal ceremony,
So that I gain durable scope, independent review, and evidence without babysitting a process.

## User value

The common path should feel like one request and one visible continuation, while the full laboratory
remains available for genuinely uncertain work.

## Acceptance criteria

- [x] Documentation leads with why to use Catfish, when not to use it, and one launch path.
- [x] LIGHT requests do not ask for duplicate implementation approval.
- [x] LIGHT progress counts only required artifacts while skipped roles remain inspectable.
- [x] A prose-only Builder cannot be mistaken for an applied repository change.
- [x] Consecutive isolated roles continue until a human or tool-capable harness is needed.
- [x] A polished local documentation site can be served natively or with Docker.
- [x] Persona findings and open-source design influences remain documented.
- [ ] Automated tests, doctor, and a strict documentation build pass.

## Out of scope

Replacing the terminal renderer with a framework, hosting a public website, publishing a GitHub
repository, or removing advanced workflow commands.

## Unknowns

Whether future users prefer a dedicated dashboard over the compact Logbook; actual use should decide.

## AI experiment required?

no

## Notes

Preserve the Product Steward, Scientist, Architect, blind Heretic, Builder, Red Team, Judge, and
Archivist names. Reduction applies to ceremony and presentation, not capability.
