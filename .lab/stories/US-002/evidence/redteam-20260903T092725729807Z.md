# Red Team Report

## Confirmed defects

- **Observation:** `GameController.send_message()` checks the message limit before awaiting `provider.chat()`, but it records the player turn only after that await completes. Two concurrent calls with `max_messages=1` can both observe zero player turns, both call the provider, and both append their messages and replies.
- **Inference:** Rapid or overlapping Send events can exceed the configured round message limit. The controller therefore does not enforce its advertised bound under concurrency.
- **Recommendation:** Reserve the player turn before awaiting the provider or serialize chat operations with a lock. Add a deterministic provider-barrier test that starts two concurrent sends with `max_messages=1` and asserts that exactly one succeeds.

## Suspected defects

- **Observation:** A chat request can pass the `CHATTING` phase check and then wait inside `provider.chat()`. During that wait, `begin_recovery()` or `abandon_round()` can change the round state. When the provider returns, `send_message()` appends the stale reply without rechecking the phase or active record.
- **Inference:** A delayed reply from an abandoned round could enter the history of a later round, or a reply could complete after recovery has begun.
- **Uncertainty:** The deterministic demo provider normally returns immediately, and supplied evidence contains no overlapping-action browser test.
- **Recommendation:** Associate each request with a round identity and active profile, then discard results if either changed while awaiting the provider.

- **Observation:** The pinned runtime evidence demonstrates startup and HTTP 200, while visual browser automation remains explicitly untested.
- **Uncertainty:** The evidence does not demonstrate that rendered buttons, async callbacks, route transitions, form entry, and the portrait work together through a complete browser round.
- **Recommendation:** Complete and record one successful and one failed round through a real Flet client or browser.

## Missing tests

- A concurrent `send_message()` test proving the configured message limit cannot be exceeded.
- A delayed-chat test where recovery begins before the provider reply returns.
- A delayed-chat test where the round is abandoned and another profile is opened before the old reply returns.
- A pinned-runtime browser test covering browse → profile → two chat messages → bank → successful result.
- The same browser flow with an incorrect answer and visible `RECOVERY FAILED`.
- A browser assertion that the seeded portrait is successfully served and rendered.
- A UI-boundary inspection proving rendered controls, callback payloads, and serialized public values contain no private recovery data.

## Design concerns

- **Observation:** Controller state mutations span asynchronous provider calls without serialization or a round-generation token.
- **Inference:** Similar stale-result and check-before-await races may appear as additional asynchronous operations are added.
- **Recommendation:** Serialize state-changing controller operations or validate a captured round identity after every awaited provider call.

- **Observation:** Route state, closure-local `runtime` state, and controller state remain separate.
- **Inference:** Correct presentation depends on synchronization among three state stores, increasing the risk of stale views during overlapping callbacks.
- **Recommendation:** Make controller phase and active profile authoritative and derive route presentation state from them where practical.

## Areas tested without finding a defect

- **Observation:** Recovery validation is deterministic and requires both accepted answers.
- **Observation:** Normalization handles Unicode normalization, case, punctuation, and whitespace deterministically.
- **Observation:** Public and private persona models are distinct, and `PublicProfile` rejects recovery data.
- **Observation:** The controller rejects mismatched private records and invalid chat-route identities.
- **Observation:** Provider failures and domain transition failures are translated to `GameControllerError`.
- **Observation:** Browse fallback actions abandon the current round and restore browsing state.
- **Observation:** The result explicitly distinguishes successful and failed recovery and presents a defensive lesson.
- **Observation:** `Settings` rejects non-positive message limits.
- **Observation:** Supplied evidence reports Ruff, Lab doctor, pytest, portrait integrity, and API-key-free pinned-runtime startup passing.
