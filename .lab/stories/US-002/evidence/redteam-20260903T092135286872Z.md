# Red Team Report

## Confirmed defects

- **Observation:** `DemoProvider` references `faces/demo-sam.png`, but the supplied `catfish/assets/` artifacts contain only `README.md`; no `faces/demo-sam.png` is present. The runtime smoke evidence verifies only that the assets directory exists.
- **Inference:** The browse card requests a nonexistent local portrait, so the intended profile image cannot load.
- **Recommendation:** Add the documented portrait at `catfish/assets/faces/demo-sam.png` and add a test resolving every seeded `portrait_asset` beneath the configured assets directory.

## Suspected defects

- **Observation:** Visual browser automation and click-through testing are explicitly untested.
- **Uncertainty:** The server returning HTTP 200 does not demonstrate that profile loading, async button callbacks, route transitions, form submission, or portrait rendering work in a browser.
- **Recommendation:** Manually or automatically complete both a successful and failed round in the pinned Flet runtime.

- **Observation:** `ChatView` ignores the `:profile_id` route parameter and relies exclusively on the closure-local `runtime["profile"]`.
- **Inference:** A URL such as `/chat/wrong-id` can display a previously selected profile rather than validating the route identity.
- **Uncertainty:** Normal button-driven navigation always supplies the active profile ID.
- **Recommendation:** Resolve and verify the route parameter against the controller’s active profile, redirecting inconsistent routes.

- **Observation:** Provider failures from `private_record()` and `chat()` are not converted to `GameControllerError`, while UI handlers catch only `GameControllerError`.
- **Inference:** A provider exception can escape the UI-safe error handling and interrupt the interaction.
- **Uncertainty:** The deterministic provider is not expected to fail during the normal demo.
- **Recommendation:** Translate provider failures at the controller boundary and test the visible fallback behavior.

## Missing tests

- A pinned-runtime browser test covering browse → open profile → two chat messages → Bank → successful result.
- The same browser flow with an incorrect answer and visible `RECOVERY FAILED`.
- A seeded-asset test proving every `portrait_asset` exists and is served.
- A route-identity test for mismatched and directly entered `/chat/:profile_id` URLs.
- UI tests proving provider profile/chat failures produce recoverable error states.
- A UI-boundary inspection proving no rendered control, callback payload, event, or serialized value contains the private record or recovery answers.
- A clean-environment launch test with API-related environment variables absent, rather than only a runtime smoke test in the existing environment.

## Design concerns

- **Observation:** Route state, closure-local `runtime` state, and controller state are maintained separately.
- **Inference:** Correct rendering depends on all three remaining synchronized, increasing the likelihood of stale or inconsistent views.
- **Recommendation:** Make controller phase and active profile identity authoritative, and validate every parameterized route against them.

- **Observation:** `create_app()` receives the complete controller, which stores the private persona record internally.
- **Inference:** Public Pydantic models prevent accidental serialization, but the UI boundary remains an in-process convention rather than a capability boundary.
- **Recommendation:** Continue boundary tests and expose a narrower UI-facing controller interface if the application grows.

## Areas tested without finding a defect

- **Observation:** Recovery succeeds only when both facts match explicit normalized variants.
- **Observation:** The debrief model rejects inconsistent success and matched-fact counts.
- **Observation:** Transition errors from recovery operations are translated to `GameControllerError`.
- **Observation:** Fallback Browse actions abandon the round and restore a usable browsing state.
- **Observation:** Public and private persona models are distinct, and `PublicProfile` rejects extra recovery data.
- **Observation:** The controller rejects a private record whose profile ID differs from the opened public profile.
- **Observation:** Canned chat, recovery validation, and the default demo configuration require no live AI call.
- **Observation:** Supplied quality-gate evidence reports Ruff, Lab doctor, pytest, and pinned-runtime startup passing.
