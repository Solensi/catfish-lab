# User Story

## Statement

As a first-time visitor or presenter, I want Catfish Lab to explain itself through one calm,
reliable interface and an honest repository front door, so that I can understand its value, run it,
and demonstrate its evidence trail without knowing its implementation history.

## User value

The project becomes approachable without losing the memorable cast, role isolation, realtime
narration, harness choice, or human authority that make the Lab distinctive.

## Acceptance criteria

- [ ] The interactive Logbook starts and exits cleanly, keeps the current story readable, exposes
      new request, continuation, harness selection, reports, help, and individual role artifacts,
      and refreshes changing role state without repaint churn.
- [ ] The default Lab context and root discovery no longer depend on the archived game specification.
- [ ] The README provides honest clone/setup paths, explains the product before its mechanics, and
      does not advertise GitHub Pages publishing.
- [ ] A prioritized improvement chart and a short live-presentation route are maintained in the
      local handbook.
- [ ] Standard contribution, security, conduct, issue, and pull-request guidance exists for a future
      public GitHub repository.
- [ ] Generated caches are absent and the Lab tests, lint, doctor, snapshots, docs build, and Docker
      configuration pass locally where the required runtime is available.

## Out of scope

Publishing a repository, publishing GitHub Pages, approving existing completion gates, redesigning
the archived game, or claiming device compatibility that CI has not exercised.

## Unknowns

The final terminal rendering still needs human review on the presentation laptop, and Docker engine
availability is environment-dependent.

no

## Notes

Prefer one strong screen, progressive disclosure, plain-language labels, visible evidence sources,
and short presentation beats. Preserve names such as the blind Heretic.
