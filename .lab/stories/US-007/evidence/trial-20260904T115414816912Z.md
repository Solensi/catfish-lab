# Completion Trial

Story: US-007

## Acceptance Criterion 1 — the Logbook is calm, reliable, and inspectable

Verdict: PASS

Evidence: `tests/test_lab_tui.py` exercises startup/exit, stable keyboard story selection, all eight
role shortcuts, new requests, Advance, human gates, live analysis refresh, durable delays, harness
choice, evidence reading, and case-file navigation. The stylesheet explicitly defines dark surfaces
and focus states for Inputs, Checkboxes, Buttons, and the Footer instead of inheriting pale defaults.

## Acceptance Criterion 2 — active context is independent of the archived game

Verdict: PASS

Evidence: initialization and context-policy tests cover a blank non-Python repository, configurable
cross-language source globs, denied secret/binary/history paths, and exclusion of `archive/`.

## Acceptance Criterion 3 — the repository front door is honest

Verdict: PASS

Evidence: `README.md` begins with the product promise, gives Docker and native clone routes, explains
the outer harness boundary and evidence location, and links only to locally served/built handbook
instructions. It does not advertise GitHub Pages publication.

## Acceptance Criterion 4 — presentation and improvement material exists

Verdict: PASS

Evidence: `docs/presentation.md` provides a timed six-minute route and failure-safe ending.
`docs/design/improvement-chart.md` prioritizes shipped, human-check, and next work, including visual
coherence and OpenCode verification. `mkdocs build --strict` passes.

## Acceptance Criterion 5 — public-project guidance exists

Verdict: PASS

Evidence: contribution, support, conduct, security, issue, pull-request, and CI files exist at their
standard repository paths and are included in the source distribution where applicable.

## Acceptance Criterion 6 — generated residue is removable and deterministic checks pass

Verdict: PASS

Evidence: `ruff check .`, `lab doctor`, all 66 tests, strict handbook build, and offline source/wheel
build pass. The built source archive contains `.opencode/agents/catfish.md`; the wheel contains the
OpenCode adapter, tutorial renderer, and TUI stylesheet. Generated build and cache directories are
removed after this trial.

## Acceptance Criterion 7 — the tutorial entrance has the Catfish identity

Verdict: PASS

Evidence: `render_tutorial_invitation` produces a bounded FIRST CAST poster with synthetic-data and
orientation disclosures, Enter/skip commands, and a text-based don't-show-again state. Its tests
cover preference toggling, ANSI styling, and colorless rendering. The existing native orientation
still waits for `b` before starting the disposable workflow.

## Acceptance Criterion 8 — OpenCode has a plausible, bounded setup path

Verdict: PASS

Evidence: `lab init` creates an OpenCode profile; the Logbook and CLI can select it. The adapter test
proves `opencode --pure run`, an attached full brief, optional `provider/model`, empty working
directory, global tool denial, and plugin/update suppression. `docs/lab/harnesses.md` gives official
installation, authentication, model discovery, selection, and outer-agent instructions, while
`.opencode/agents/catfish.md` defines the tool-capable repository proxy.

## Red Team Findings

No deterministic defect was reproduced. The Red Team correctly limits the claim: executable
discovery is not an authentication probe; OpenCode and terminal-font behavior need human-machine
checks; and the selected role provider must remain distinct from the tool-capable outer agent.

## Overall Verdict

READY
