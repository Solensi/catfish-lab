# Completion Trial

Story: US-007

## Acceptance Criterion 1 — the main case text is keyboard-readable

Verdict: PASS

Evidence: the Logbook labels the pane route; Tab or Right focuses `CaseScroll`, `j`/`k` and arrows
scroll it, and Left returns to `StoryList`. A headless test verifies positive scroll position and an
unchanged active story.

## Acceptance Criterion 2 — rejecting an assessment requires a reason

Verdict: PASS

Evidence: final Advance exposes **Send back [r]**, which opens a focused feedback prompt. Both the
controller and UI refuse empty feedback. The CLI equivalent requires `--reason`.

## Acceptance Criterion 3 — feedback reaches remediation rather than disappearing

Verdict: PASS

Evidence: rejection writes a hashed `evidence/human-feedback-*.md`, preserves the superseded
implementation, Red Team report, and trial, resets their claims, and makes the next action
`lab run builder STORY --harness`. `lab inbox --json` exposes the feedback reason and artifact path,
and the Builder context policy includes the feedback document.

## Acceptance Criterion 4 — evidence narration remains attributable

Verdict: PASS

Evidence: Live Analysis recognizes `assessment_rejected`, attributes the decision to the human,
quotes the reason, and reports whether the feedback artifact still matches its recorded SHA-256.
Case files discovers both feedback and superseded artifacts beneath `evidence/`.

## Acceptance Criterion 5 — the repository launch has one documented path

Verdict: PASS

Evidence: `docs/repository-launch.md` documents the official Arch GitHub CLI, Docker, Compose, and
Buildx packages; Docker service setup; native and container verification; local Git identity and
history; GitHub CLI authentication; repository creation or remote attachment; push; and post-push
Actions verification. It explicitly rejects Pages and substitute container runtimes as evidence.

## Acceptance Criterion 6 — deterministic and container quality checks pass

Verdict: PASS

Evidence: Ruff passes; all 71 tests pass; `lab doctor` passes; MkDocs builds in strict mode; offline
source and wheel builds pass. A live `catfish-lab:local` image build completed with Docker 29.7.2,
then the containerized doctor passed and the containerized Logbook rendered a verified snapshot.
The snapshot made the unavailable host harness visible as `DELAYED` while remaining operational.

## Red Team Findings

No requested defect was reproduced. The live Docker check found a missing local Buildx plugin; the
official Arch package and its proof command were added to the launch guide. Remaining concerns are
bounded to human visual review, host/provider combinations not available here, and GitHub Actions,
which cannot run before the first push.

READY
