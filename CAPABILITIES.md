# Catfish Lab in 10 lines

1. Accept ordinary project work in the Logbook or CLI; LIGHT is the default and FULL adds research.
2. Preserve the original request and every role handoff as readable repository artifacts.
3. Run Product, Scientist, Architect, blind Heretic, Red Team, Judge, and Archivist in fresh context.
4. Hand real file changes to the surrounding tool-capable coding harness; never fake implementation.
5. Switch text roles among Codex, Claude Code, OpenCode, and local Ollama from the Logbook.
6. Narrate progress, sources, failures, and blockers; make both story and case text keyboard-readable.
7. Keep human authority visible; rejected final assessments require reasons and queue remediation.
8. Seal run metadata and artifact hashes in an integrity-linked ledger; archive path-cited evidence.
9. Reopen rejected work without erasing the superseded review.
10. Learn through the first-run tutorial; verify with `lab doctor`; run natively, in Docker, or CI.
