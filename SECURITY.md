# Security policy

Catfish Lab stores prompts, role outputs, file paths, hashes, and human decisions inside the project.
Do not submit credentials, private recovery data, personal secrets, or confidential prompts to the
Lab or to a public issue.

## Reporting a vulnerability

Use GitHub's private vulnerability-reporting form from the repository **Security** tab when it is
enabled. If no private form is available, contact the maintainer through their GitHub profile and ask
for a private reporting channel before sharing details. Do not open a public issue containing an
exploit, secret, or sensitive artifact.

Include the affected version or commit, impact, minimum reproduction, and any suggested containment.
The maintainer should acknowledge receipt, establish a private update cadence, and coordinate a fix
and disclosure. No response deadline is promised before the project has a published maintainer rota.

## Supported versions

Catfish Lab is pre-1.0. Only the latest commit on the default branch is currently supported. This
section will become a version table when the first release is cut.
